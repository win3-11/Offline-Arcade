# Offline Arcade

Сайт с четырьмя мини-играми, которые работают **без интернета**: 2048, Змейка, Сапер, Тетрис.

Ноль зависимостей, ноль фреймворков — только чистый JavaScript, CSS и Service Worker.

## Быстрый старт

Нужен только **Node.js** (проверь: `node -v`). Ничего устанавливать не нужно —
нет ни `npm install`, ни зависимостей.

### Хочу просто играть, без сервера

```powershell
node build.mjs
```

Открой `dist/offline-arcade.html` двойным кликом. Готово.

### Хочу полный режим (установка как приложение, кеш, иконка в меню)

```powershell
node server.mjs 8099
```

Открой <http://localhost:8099>.

## Два способа запуска

Разница между режимами не в играх, а в том, как браузер относится к источнику файлов.

### Режим 1 — один файл, `file://`

```powershell
node build.mjs
# → dist/offline-arcade.html, ~66 КБ
```

**Что происходит.** `build.mjs` берёт все 10 модулей, склеивает их в один
`<script>`, встраивает CSS прямо в `<style>`, а иконку — как `data:`-ссылку.
Получается файл, в котором нет ни одной внешней ссылки.

**Плюсы:** открывается двойным кликом, можно положить на флешку, отправить
другу в мессенджере, работает вообще без интернета.

**Минусы:** нельзя установить как приложение. Service Worker на `file://`
запрещён браузерами, поэтому офлайн-кеша и иконки в меню не будет.

### Режим 2 — через сервер, `http://`

```powershell
node server.mjs 8099
# → http://localhost:8099
```

**Что происходит.** `server.mjs` — крошечный статический сервер на встроенном
`node:http`. Он ничего не делает, кроме как отдать файлы с диска по HTTP.

**Плюсы:** полноценный PWA — Service Worker кеширует всё, сайт ставится как
отдельное приложение, на телефоне добавляется на главный экран.

**Минусы:** нужно запускать сервер. Подойдёт любой статический сервер
(`npx serve`, `python -m http.server`) — нужен именно HTTP, а не `file://`.

### Почему нельзя просто открыть `index.html` с диска

Браузер блокирует ES-модули для `file://`:

```
Access to script at 'file:///D:/…/js/app.js' from origin 'null'
has been blocked by CORS policy
```

Модули подразумевают загрузку через HTTP, где есть заголовки и права.
На `file://` их нет, поэтому браузер их отклоняет. Именно поэтому существует
`build.mjs` — он делает так, чтобы с диска грузить было нечего: весь код
уже внутри файла.

## Что где лежит и зачем

### Корневые файлы

| Файл | Зачем он |
|---|---|
| `index.html` | Точка входа **для режима 2**. Подключает стили и `js/app.js`. Открывается только через сервер. |
| `manifest.webmanifest` | Манифест PWA. Описывает имя, цвета, иконки и режим `standalone` — ради этого браузер предлагает «Установить приложение». |
| `sw.js` | Service Worker. Скачивает все файлы в кеш при первом визите, чтобы потом сайт открывался без сети. |
| `server.mjs` | Мини-сервер на `node:http` для локального запуска. Нужен только для разработки. |
| `build.mjs` | Сборщик. Склеивает модули, CSS и иконки в один `dist/offline-arcade.html`. |
| `README.md` | Этот файл. |

### `css/styles.css`

Дизайн-система целиком в одном файле: две темы через CSS-переменные, карточки,
кнопки, поля для всех четырёх игр, оверлеи результата, адаптив под телефон.

Темы сделаны на CSS-переменных: переключение меняет одну строку `data-theme`
в `<html>`, а все цвета подтягиваются автоматически. Поэтому в коде нигде нет
условий вида «if (dark)» и захардкоженных цветов.

### `icons/`

- `icon.svg` — обычная иконка приложения.
- `icon-maskable.svg` — та же иконка, но с увеличенными отступами. Android
  обрезает нестандартные иконки по своей маске, и без отступов содержимое
  обрезалось бы по углам.

### `js/` — ядро приложения

| Файл | Зачем он | Что внутри |
|---|---|---|
| `app.js` | Входная точка. Собирает всё воедино. | Регистрирует маршруты, рисует главный экран, переключает тему, регистрирует Service Worker. |
| `nav.js` | Роутер. Переключает экраны. | Хеш-роутинг, шапка приложения, защита от гонки при быстрых переходах. |
| `storage.js` | Всё, что связано с `localStorage`. | Рекорды, настройки, автосохранение партий. |
| `utils.js` | Мелкие помощники, общие для всех игр. | Создание DOM-элементов, свайпы, клавиатура, звуки. |
| `icons.js` | Иконки. | SVG-иконки в духе Lucide, встроенные прямо в код. |

**Почему `nav.js` отдельный файл.** Раньше навигация жила в `app.js`, а игры
импортировали её оттуда. Получался цикл: `app.js` → игра → `app.js`. Обычный
браузер это терпит, а сборщик — нет: непонятно, какой файл грузить первым.
После разделения граф импортов стал деревом, и `build.mjs` заработал.

**Почему `icons.js`, а не библиотека.** Оригинальное задание просило Lucide
Icons. Останавливать Lucide через CDN нельзя — при первом же офлайне иконки бы
исчезли, а это противоречит всей идее проекта. Поэтому иконки написаны вручную
в виде строк SVG: они занимают 2.7 КБ и работают всегда.

### `js/games/` — сами игры

| Файл | Игра |
|---|---|
| `index.js` | Реестр игр: название, описание, цвет карточки. Из него строится главный экран. |
| `game2048.js` | 2048 |
| `snake.js` | Змейка |
| `minesweeper.js` | Сапер |
| `tetris.js` | Тетрис |

Каждая игра — самостоятельный модуль с единственной функцией `render()`.
Она возвращает `{ node, dispose }`: `node` — элемент с интерфейсом,
`dispose` — функция очистки (остановить таймеры, снять слушатели клавиатуры).
`nav.js` вызывает `dispose` при уходе на другой экран, чтобы старые таймеры
не крутились в фоне.

Добавить новую игру — значит создать файл в `js/games/` с функцией `render()`
и добавить строчку в `js/games/index.js` и в `app.js`. Больше нигде трогать
не нужно.

### `dist/offline-arcade.html`

Сгенерированный файл для режима 1. **Вручную его редактировать нельзя** —
он перезаписывается при каждом запуске `build.mjs`. Правится исходный код,
потом пересобирается.

### `test/`

| Файл | Что проверяет |
|---|---|
| `dom-shim.mjs` | Минимальная реализация DOM, чтобы запускать игровые модули в Node без браузера. |
| `logic.test.mjs` | Игровая логика: ходы, счёт, сохранение, безопасный первый клик в сапере. |
| `nav.test.mjs` | Навигация: кнопка «Играть», возврат в меню, вход по прямой ссылке. |
| `layout.test.mjs` | Вёрстка: у всех CSS-сеток объявлены колонки. |
| `bundle.test.mjs` | Собранный файл: нет внешних запросов, скрипт парсится, игры открываются. |

## Как это устроено внутри

### Переключение экранов

Работает по хешу: `#/g2048`, `#/snake`, `#/mines`, `#/tetris`, `#/home`.
Поэтому ссылку на конкретную игру можно сохранить или отправить другу.

Два нюанса, на которые ушло больше всего времени:

1. **`navigate()` вызывает `render()` напрямую**, а не только меняет хеш.
   Иначе при входе по прямой ссылке на `#/g2048` экран навсегда зависал
   на надписи «Загрузка…».
2. **Защита от гонки.** Если кликнуть быстро несколько раз, асинхронная
   загрузка модулей могла дорисовать старый экран поверх нового. Решает
   счётчик `token`: кто начал рендер последним, тот и победил.

### Как написан код без фреймворка

Вместо шаблонов используется крошечный хелпер:

```js
el('div', { class: 'card' }, 'Текст', el('span', { text: 'Ещё текст' }))
```

Никакого virtual DOM, никакой сборки — `el()` напрямую создаёт элементы
через `document.createElement`. Для проекта такого размера это проще и быстрее,
чем подключать React.

### Почему `icon()` и `iconEl()` — два разных вызова

Это не дублирование, а защита от типовой ошибки.

`icon('grid')` возвращает **строку** с разметкой `<svg>…</svg>`. Такая строка
подходит только для свойства `html:` (это `innerHTML`).

`iconEl('grid')` возвращает **настоящий SVG-узел**, который можно передать
как дочерний элемент.

Когда иконки вставляли строкой в дочерние элементы, на экране появлялся
буквально исходный код `<svg xmlns=…>`. Теперь в `el()` есть проверка:
если в дочерние элементы попала строка с разметкой, в консоль падает
предупреждение.

### Сборщик `build.mjs`

Собственными силами, без Rollup и esbuild. Алгоритм:

1. Обходит граф импортов от `js/app.js` рекурсивно.
2. Сортирует модули так, чтобы зависимости шли раньше зависимых.
3. Каждый модуль оборачивает в IIFE — функцию, выполняемую сразу.
   Это даёт каждому модулю **свою область видимости**.
4. Импортированные имена превращает в `const`-алиасы:
   `import { el } from './utils.js'` → `const el = m_js_utils.el;`
5. `export` в объявлениях убирает, экспортируемые имена собирает в `return`.
6. Ленивые `import('./games/snake.js')` превращает в `Promise.resolve(модуль)`.

**Зачем IIFE.** Если просто склеить модули в один скрипт, переменные с
одинаковыми именами столкнулись бы. Например, в `snake.js` и `minesweeper.js`
есть `let level` — без обёрток одна игра перетирала бы переменную другой.
IIFE изолирует каждую.

### Ручной `parseImports` вместо `node:module`

В сборщике свой разбор `import`/`export` регулярками. Стандартный
`node:module` тут не помогает — он рассчитан на CommonJS и не отдаёт
готовый список имён для трансформации.

## Игры и управление

### 2048

Классика на сетке 4×4. Плитки соединяются, если совпадают, цель — 2048.
После достижения 2048 можно продолжить игру до поражения.

**Управление:** стрелки или `WASD` на ПК, свайпы по полю на телефоне.

**Сохранение:** вся доска и счёт. Закрыл вкладку — вернулся, партия на месте.

### Змейка

Поле 20×20, еда появляется случайно, счёт растёт на 10 за каждую еду.
Скорость повышается по мере роста: от 150 мс на шаг до 60 мс.

**Управление:** стрелки или `WASD`, пробел — пауза. На телефоне — свайпы
и экранный D-pad под полем.

**Важная деталь:** разворот на 180° запрещён. Без этого можно было бы
развернуться и тут же врезаться в собственный хвост.

### Сапер

Три сложности:

| Уровень | Поле | Мин |
|---|---|---|
| Лёгкий | 9×9 | 10 |
| Средний | 16×16 | 40 |
| Сложный | 24×16 | 70 |

**Первый клик всегда безопасный.** Мины расставляются не в начале партии,
а в момент первого клика — причём защищённой делается зона 3×3 вокруг него.
Поэтому первое открытие всегда даёт осмысленный результат, а не пару
просто пустых клеток.

**Флажки:** правая кнопка мыши на ПК, долгий тап (420 мс) на телефоне.

**Таймер** идёт с первого клика и останавливается при победе или взрыве.
Рекорд — лучшее время победы, он переживает перезагрузку.

### Тетрис

Поле 10×20, все 7 классических фигур. Фигуры выпадают из «мешка» — так
последовательность честно случайная, без повторов подряд.

**Управление:** `←` `→` — движение, `↓` — ускоренное падение, `↑` или `X` —
поворот, `Пробел` — сбросить всё сразу, `Esc` — пауза. На телефоне — свайпы
и кнопки под полем.

**Поворот с отступом.** Если фигура не помещается повёрнутой у стены или на
дне, сборщик пробует сдвинуть её на клетку влево или вправо — это называется
«кик». Без этого пришлось бы ждать, пока фигура отодвинет стеной.

**Ускорение** каждые 10 линий, максимум — 90 мс на ряд.

## Хранение данных

Всё лежит в `localStorage` под префиксом `offline-arcade:`.

| Ключ | Что хранит |
|---|---|
| `offline-arcade:scores` | Рекорды по каждой игре: `{ g2048: { best: 4096, bestAt: ... } }` |
| `offline-arcade:settings` | Тема и включён ли звук |
| `offline-arcade:states` | Незаконченные партии (доска 2048, выбранный уровень сапера) |

Слой хранения изолирован в `js/storage.js`. Игры вызывают `scores.submit(id, 100)`
и не знают, как устроен `localStorage`. Захочешь поменять хранилище на
IndexedDB — правится один файл.

Все операции обёрнуты в `try/catch`: в приватном режиме некоторых браузеров
запись запрещена, и игра просто продолжит работать без сохранения.

## Темы и звук

**Темы.** Переключатель в шапке, выбор сохраняется. Реализация — CSS-переменные:
в `styles.css` описаны два набора переменных под `[data-theme="dark"]` и
`[data-theme="light"]`, а JS меняет один атрибут. Цвет `theme-color` в `<meta>`
тоже обновляется — иначе на телефоне осталась бы старая полоса браузера.

**Звук.** Короткие «бипы» на WebAudio, генерируются кодом, аудиофайлов нет —
это ещё один способ не тянуть зависимости. По умолчанию выключен, включается
кнопкой в шапке. Частота тона зависит от очков в 2048 — затянувшийся ход
слышно по высоте звука.

## Offline-first: как это работает

`sw.js` реализует две стратегии, потому что для навигации и для файлов они
оптимально разные.

**Навигация — network-first.** Сначала пробуем сеть, при неудаче берём из кеша.
Так пользователь получает свежую версию сайта, если есть интернет, но всё
равно не увидит «offline»-страницу без сети.

**Файлы — cache-first.** Сначала кеш, параллельно обновляем его из сети.
Для игры это правильно: код не меняется между релизами, а скорость важнее.

**Кеш версионируется.** В `sw.js` есть константа `VERSION`. При изменении
любого файла её нужно поднять — тогда при следующем визите старый кеш удалится
и скачается свежий. Без этого пользователи долго видели бы старую версию.

**Что кешируется.** `sw.js` явно перечисляет все файлы в массиве `ASSETS`.
Список задан руками намеренно: он короткий и стабильный.

## Тесты

Тесты запускаются обычным `node`, без `npm` и без браузера.

```powershell
node test/logic.test.mjs   # 23 теста игровой логики
node test/nav.test.mjs     # навигация между экранами
node test/layout.test.mjs  # вёрстка
node build.mjs             # пересобрать dist/
node test/bundle.test.mjs  # проверить сборку
```

### Зачем нужен `dom-shim.mjs`

Игровые модули — обычный JavaScript, который создаёт элементы через
`document.createElement`. Чтобы проверить их в Node, нужен DOM. Playwright
в системе нет, а ставить его нечем. Поэтому написан минимальный шим: узлы
с классами, детьми, слушателями и синхронной диспетчеризацией событий.

Это позволяет гонять **настоящие игровые модули**, а не их копии: если
сломать сдвиг плитки в `game2048.js`, тест это поймает.

### Зачем тестам такие названия

Названия тестов — это ожидаемое поведение на человеческом языке. Когда падает
тест, сразу понятно, что сломалось:

```
ok   первый клик безопасен — открылась область
FAIL ПКМ ставит флажок → flag=0
```

## Частые проблемы

**Пустой экран или «Не удалось открыть игру».**
Скорее всего, открыт `index.html` двойным кликом. Так не работает —
нужен либо `dist/offline-arcade.html`, либо сервер.

**Игра не обновилась, хотя код менялся.**
Дело в Service Worker. Открой DevTools → Application → Service Workers и
нажми Unregister, либо подними `VERSION` в `sw.js` и обнови страницу
с `Ctrl+F5`.

**Сетка выехала в одну колонку.**
Так ведёт себя `display: grid` без `grid-template-columns`. Проверить можно
тестом `layout.test.mjs` — он специально ловит такие случаи.

**Иконки превратились в текст `<svg …>`.**
Строка разметки попала в дочерние элементы вместо свойства `html:`.
Используй `iconEl()`. `el()` теперь предупреждает об этом в консоли.

**`dist/offline-arcade.html` ведёт себя странно.**
Он не пересобран: изменения в `js/` в него не попадают автоматически.
Выполни `node build.mjs`.

## Как развивать дальше

**Добавить игру.** Создай `js/games/pingpong.js` с функцией `render()`,
возвращающей `{ node, dispose }`. Добавь запись в `js/games/index.js`
(название, описание, цвет) и в `app.js` (строка `register(...)`).
Дальше — `node build.mjs`.

**Сделать офлайн для обоих режимов.** Нужен HTTPS — Service Worker не
работает на `file://`. При деплое на любой статический хостинг с HTTPS
(GitHub Pages, Netlify, Cloudflare Pages) всё заработает само: файлы уже
на месте, `sw.js` их закэширует.

**Убрать хеш из адресной строки.** В `nav.js` заменить `location.hash`
на `history.pushState` + `popstate`. Сейчас хеш выбран сознательно: он
работает и на `file://`, и без настройки сервера, что важнее красоты URL.
